# Split the dashboard before it misleads

Ticket 06 as written will produce a bad frontend because it compresses three unrelated products — an async audio-review workbench, a real-time voice-control demo, and an evaluator-facing metrics dashboard — into fourteen lines and four checkboxes with no routing, no state machines, and no honesty constraints, which invites exactly the failure this project can least afford: a single crammed page where experimental Detections read as reliable results. The stakes are concrete. The sliding-window detector measured **event-F1 0.007 with 1,559 false alarms/hour** on held-out meeting speech, most false Detections scoring **≥0.85**, so no threshold tweak rescues it ([Source](file://docs/adr/0006-sliding-window-gate-no-go.md)); any UI that renders those Detections without Confidence-only framing, run provenance, and an experimental banner actively misleads its user. The fix is structural, not cosmetic: give each slice its own route and job model, link waveform regions to table rows bidirectionally with keyboard parity, gate the microphone behind explicit consent with a visible cooldown, and split isolated-clip metrics from continuous-event metrics behind run-based provenance. This report lays out that redesign grounded in the three research notes and the repo's actual contracts — FastAPI on **127.0.0.1:8000**, Next.js on **127.0.0.1:3000**, six Keywords **left/right/up/down/go/stop** plus Unknown/Silence, **40 MiB/600 s** upload ceilings, and the **queued/running/completed/failed** lifecycle.

## Ticket 06 crams three products into fourteen lines

Ticket 06 reads as a feature list rather than a buildable specification, and every vague phrase in it predicts a concrete UI failure. "Audio Analysis with upload, Keyword chips, progress, waveform regions with click-to-seek/play, sortable Detection table, and delete" collapses at least six distinct states into the word "progress": client-side upload progress, server **queued** position behind a single worker with two waiting jobs, **running** inference, terminal **completed/failed**, plus the empty **no_detections** outcome that returns HTTP 200 with an empty list ([Source](file://docs/backend-api.md)). An implementer handed that sentence builds one spinner, so users cannot tell whether their file is uploading, waiting behind another job, or stuck — and the polling contract the backend mandates ("poll Recording metadata until terminal status") never appears in the ticket at all. The waveform clause is equally thin: "click seeks and plays the segment" says nothing about zoom for inspecting **~1.0 s windows on a 0.2–0.25 s stride**, nothing about what happens when regions overlap, nothing about which region is active during playback, and nothing about keyboard users for whom a canvas waveform is effectively invisible. Best-in-class review tools hold one invariant the ticket never states — waveform region, list row, and audio clock stay bidirectionally linked with zoom and per-class colors — with Label Studio's audio tag playing waveform-backed regions navigable by click, playhead drag, and time/amplitude zoom ([Source](https://labelstud.io/blog/labeling-audio-data-with-label-studio)) and Encord's editor snapping region boundaries to the playhead with merge and copy-paste affordances ([Source](https://docs.encord.com/platform-documentation/Annotate/annotate-label-editor/annotate-audio)). Without that invariant written down, the ticket's waveform and table will be built as two disconnected widgets showing the same data.

The Voice Control checkbox fails differently: it names the right nouns (six Keywords, dedup, cooldown, immediate stop) but specifies no interaction contract. It never says the microphone must start only on explicit user gesture, never defines what "live status" contains, never distinguishes pausing media (the **stop** Keyword's in-app action) from stopping the mic session, and never mentions that a denied permission is sticky per origin so re-calling `getUserMedia` will not re-show the prompt ([Source](https://webrtc.smnandre.dev/calls/capture)). The dashboard checkbox is the most dangerous underspecification of all: "run-based training curves, confusion matrix, isolated versus event metrics, and `Not evaluated` empty states" never says which runs exist, what switching or deleting a run does to the view, where the fixed **≥0.85 macro-F1 / ≥0.70 event-F1** targets render, or that the continuous tab must carry an experimental banner linking the frozen detector JSON. Only one of three required empty states is named — **Not evaluated** — while **target-unmet** and **run-deleted** go unmentioned, which is precisely how a **0.74 macro-F1** and a **0.007 event-F1** end up displayed as bare numbers an evaluator reads as success. Finally, the four-state error line ("corrupt-file, empty-result, mic-denied, offline-backend") omits the backend's actual error vocabulary — **409 duplicate/in-progress, 429 queue-full/rate-limited, 413 too-large/too-long, 503 model/worker unavailable** ([Source](file://docs/backend-api.md)) — so recovery copy ("retry", "wait", "reload demo") cannot be written from the ticket. The common thread is architectural: three slices with different data sources (durable job store, ephemeral mic stream, static run JSON), different tempos (minutes, milliseconds, eternal), and different honesty obligations are described as one ticket with no routing decision, which funnels implementers toward a single crowded page where a live mic meter sits beside an experimental confusion matrix and every number contaminates its neighbor.

## Give each slice its own route and its own job model

The single highest-leverage redesign decision is information architecture: **three separate routes, not one page**. Analysis (`/analyze`), Live (`/live`), and Dashboard (`/dashboard`) each own a distinct layout, data lifecycle, and honesty banner, sharing only a global backend-status pill and the active-model indicator from `GET /api/models/active`. A single page forces the waveform, the mic meter, and the confusion matrix to compete for one viewport and one mental model; separate routes let Analysis optimize for a wide waveform-plus-table workbench, Live optimize for a glanceable demo stage with an unmissable LISTENING indicator, and Dashboard optimize for evaluator-grade charts with denominators attached. Cross-links carry context instead of sharing chrome: the Analysis empty state links to the Dashboard's isolated-classification tab for what Confidence means, Analysis Detections link the frozen detector config, and the Dashboard's continuous tab links back to a sample Analysis session. Within Analysis, the async job UX must make the durable server state machine visible rather than papering it over with a spinner. The exemplar pattern from async upload implementations is a **pending → processing → success|failed** modal with percent progress, an explicit queued message, polling every couple of seconds, and inline error plus retry ([Source](https://raw.githubusercontent.com/zhouxiaoka/autoclip/main/frontend/src/components/UploadModal.tsx)), while accessible upload primitives announce aggregate state through a hidden `role="status"` live region with per-file progress in reading order ([Source](https://www.ariaui.dev/docs/components/upload)). Adapted to this repo, that means polling `GET /api/recordings/{id}` plus `.../detections` at roughly **1–2 s with backoff** until a terminal status, distinct chips for each state (`uploaded` grey "ready to analyze", `queued` amber pulsing, `running` blue animated with a "disconnects do not cancel" note, `completed` green with count, `failed` red with stored error code and recovery action), and client pre-checks before POST — **.wav extension, non-empty, ≤40 MiB, ≤600 s** via header peek — showing filename, duration, channels, rate, and the supported Keywords before Analyze is enabled. The completed-but-empty outcome deserves its own designed panel ("No Detections — no Keyword met threshold", `no_detections` shown subtly for debuggability) rather than an empty table that reads as a loading bug, and corrupt files get actionable errors mapped from the backend's `invalid_wav/unsupported_wav` 400s with a retry path. Queue-full **429** says "try again shortly", duplicate-analysis **409** disables the Analyze button while `queued/running`, and **503** model/worker states surface as an offline-backend banner with a single recovery action — each failure carrying one line of cause plus one click of recovery, the same discipline production streaming guidance applies to disposable WebSocket sessions ([Source](https://developers.telnyx.com/docs/voice/stt/websocket-streaming/production-patterns)).

| Frontend state | Backend truth | Visual treatment |
|---|---|---|
| Uploading | Multipart POST in flight (2 upload slots, 60 req/min) | Determinate percent bar, cancel affordance |
| Queued | `queued` behind single worker, 2 waiting jobs | Amber pulsing chip, position if known, 429 → "queue full, retry shortly" |
| Running | `running`, disconnects do not cancel | Blue animated bar, "safe to navigate away", no cancel (durable job) |
| Completed with Detections | `completed`, Detection array | Green chip with count, waveform regions render |
| Completed empty | HTTP 200 `code: no_detections` | Designed empty panel, never a blank table |
| Failed | `failed` + stored `error_code` | Red chip, code shown, Retry re-queues analysis |

## Analysis review links waveform, table, and clock both ways

The Analysis slice should be designed as a review workbench obeying the invariant the ticket omits: **region, row, and clock stay bidirectionally linked**. For waveform rendering inside Next.js, **wavesurfer.js v7 with the Regions, Timeline, Hover, and Zoom plugins is the lowest-friction choice** for click-to-seek plus zoom plus region highlight. Regions are visual overlays that can be clicked and played back independently, created after load with `regions.addRegion({start, end, color, content})` ([Source](https://wavesurfer.xyz/docs/plugins/regions)), with the canonical click-to-play pattern halting propagation and playing the region to its end ([Source](https://wavesurfer.xyz/docs/plugins/regions)), a full lifecycle of `region-clicked/in/out/created/updated` events for row synchronization ([Source](https://github.com/katspaugh/wavesurfer.js/blob/main/_autodocs/api-reference/plugin-regions.md)), a virtualized time ruler with configurable formatting such as `m:ss` ([Source](https://github.com/katspaugh/wavesurfer.js/blob/main/_autodocs/api-reference/plugin-timeline.md)), and scroll/pinch zoom ([Source](https://github.com/katspaugh/wavesurfer.js/blob/main/_autodocs/api-reference/plugin-zoom.md)). The credible alternative is **peaks.js** with its `zoomview` plus `overview` containers, `setZoom({seconds})` seeking, and segment drag modes ([Source](https://github.com/bbc/peaks.js/blob/master/doc/API.md)) — the right call only if the 10-minute ceiling makes single-canvas decode sluggish on the Ryzen 5 5500U target, in which case an overview-plus-detail layout earns its heavier integration. Raw Web Audio canvas remains fallback-only. Concretely: render client-only (`'use client'` plus SSR-disabled dynamic import), load audio from `/api/recordings/{id}/audio` which supports byte ranges, create one read-only region per Detection (**drag and resize disabled**, Keyword label plus Confidence as region content), keep a Detection-to-region-id map, and drive the active row from `region-in/out` and `timeupdate`. Per-Keyword colors with a legend, a timeline ruler, playhead-drag plus click-to-seek, and zoom controls complete the Label Studio/Encord affordance set, while Descript's wordbar lesson — every waveform span names the words it represents ([Source](https://help.descript.com/hc/en-us/articles/10249346632717-The-wordbar)) — becomes region content plus clickable `m:ss.mmm` timestamp chips in the table that seek with a small pre-roll around **0.2 s**.

The Detection table must be a dense, sortable, filterable seek control, not a readout. Columns are **Keyword (multi-select filter chips defaulting to the analyzed set)**, **Start/End (timestamp buttons, numeric sort)**, **derived Duration (judges the ~1 s window plausibility)**, **Confidence (bar plus numeric, labeled "score, not correctness", numeric sort)**, **Threshold (frozen detector config, tooltip)**, and a **Play row action**, defaulting to Start-ascending sort with Confidence-descending available for triage. Interaction is symmetric: hovering a row outlines its region, the active row carries `aria-current` during playback, clicking a row seeks and plays, and clicking a region selects the row and scrolls it into view. Keyword filter chips dim non-matching regions, borrowing Otter's keyword-search-to-jump navigation ([Source](https://otter.ai/speech-to-text)). Two honesty mechanisms are non-negotiable. First, a header banner stating the detector is experimental with approximate times and Confidence-is-not-accuracy, linking the E02 feasibility run. Second, delete scoped honestly: the P0 API has **no per-Detection delete** — only Recording-level `DELETE` cascading to audio, metadata, and child Detections with 204 on success — so the UI offers one confirm modal ("deletes audio bytes plus N Detections irreversibly"), disabled during `queued/running` where it would 409, with optimistic list removal and a toast carrying the backend code on failure. Accessibility is a parallel implementation track, not polish: canvas waveforms are pointer-centric, so Prev/Next Detection buttons, ±1 s/±5 s seek, spacebar play/pause, a listbox of Detections that seeks identically, keyboard-operable sort headers with `aria-sort`, and the `role="status"` live region for job state are what make the workbench operable without a mouse.

## Live voice demo gates consent before streaming a frame

The Live slice has a privacy architecture before it has a layout: **the Start button is the only trigger for `getUserMedia`, AudioWorklet construction, and WebSocket open, and Stop, disconnect, or tab-hide must release every track, close the socket, and suspend the context**. Browsers require permission before any mic opens and must ask at least on first use ([Source](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)), while a lit mic indicator means tracks were never stopped — full release requires `track.stop()` on every track, with `enabled=false` reserved for reversible mute ([Source](https://webrtc.smnandre.dev/calls/capture)). The Porcupine web demo sets the right precedent by requesting permission at subscribe time rather than page load, after worker and audio-processor initialization ([Source](https://github.com/Picovoice/porcupine/tree/master/demo/web)). Error handling must branch on `err.name`, never message strings — `NotAllowedError` for denied or blocked, `NotFoundError` for no device, `OverconstrainedError` for constraint relaxation, `NotReadableError` for OS-held devices ([Source](https://webrtc.smnandre.dev/calls/capture)) — and critically, once an origin is denied, re-calling `getUserMedia` will not re-show the prompt, so the UI must teach the settings fix with per-browser lock-icon steps instead of looping re-requests. The session state machine is **idle → requesting → listening → reconnecting → stopped** plus an error branch, each state owning exactly one recovery button, with a persistent red LISTENING pill, animated level bar, and elapsed timer so background running is impossible to miss. Liveness proof separates "mic alive" from "Detection emitted": an RMS-driven meter at `requestAnimationFrame` cadence sampling the AnalyserNode with dB mapping and clipping flags ([Source](https://webrtc.smnandre.dev/calls/audio)), optionally via the AudioWorklet volume-meter pattern posting volume messages roughly every 25 ms ([Source](https://stackoverflow.com/questions/62702721/how-to-get-microphone-volume-using-audioworklet)), plus a VAD dot (Silence/Unknown/speech) in the hark tradition of threshold-plus-history speech gating ([Source](https://webrtchacks.com/getusermedia-volume/)). The "no raw mic stored" privacy line sits beside the meter at all times, per ADR-0003's no-retention default.

One-utterance-one-action is enforced visibly through a **~1.2 s cooldown** that sits between the 400 ms game-voice guard used with 0.80 probability thresholds and 0.50 overlap factors ([Source](https://deepwiki.com/joy-andraos/hci-snake-game/4.3-voice-control-(tensorflow-speech-commands))) and the multi-frame consecutive-positive discipline of wake-word engines ([Source](https://mycroft-ai.gitbook.io/docs/using-mycroft-ai/customizations/wake-word)): long enough to swallow ring-buffer repeats, short enough for slide pacing, rendered as a countdown ring on the last-Detection card with Keyword chips dimmed during lockout. That card is the demo's unit of truth — **Keyword label, Confidence, accepted/rejected decision, and action result** ("slide→3", "paused") — with a ~20-row history in green accepted versus grey-amber rejected language, where Unknown, Silence, low-Confidence, and cooldown-hits are logged as visibly as acceptances. Smoothing (N consecutive frames above threshold with cooldown expired) precedes emission; the rejected path still logs for transparency. The demo stage itself splits into a slide pane (large index, prev/next arrows flashing on left/right Detections), a transport cluster (play/pause icon swapping on go/stop), a volume bar (up/down steps), a per-row **utterance-end-to-action latency chip targeting under 500 ms local loopback**, and a cooldown bar — with a side legend mapping all six Keywords to keyboard equivalents, voice and keyboard calling the same `dispatchAction()` so fallback is identical, and strict ADR-0004 allowlisting where each Keyword maps to exactly one in-app function and nothing touches the OS. Streaming hygiene follows production practice: versioned handshake, **2–8 KB binary frames**, `bufferedAmount` backpressure with a slow-connection notice and stale-frame drops that are logged never silent, keepalive, explicit end markers, and bounded exponential-backoff reconnect ([Source](https://developers.telnyx.com/docs/voice/stt/websocket-streaming/production-patterns)) — with Detection history and cooldown paused during reconnect so one utterance can never double-count.

## Evaluation dashboard separates clips from streams and proves provenance

The Dashboard slice exists for one reader — the course evaluator deciding whether any number can be trusted — and its governing rule comes straight from ADR-0005: **every number traces to a persisted Evaluation Run, isolated-clip metrics and continuous-event metrics never share a view, and unlabeled audio shows Confidence only**. The visualization grammar follows experiment-tracking best practice: synchronized train-versus-validation loss and accuracy curves on a shared epoch axis with a best-epoch marker (the TensorBoard scalars and MLflow per-epoch time-series pattern ([Source](https://www.tensorflow.org/tensorboard/get_started))), where the overfit signature — training loss falling while validation loss rises ([Source](https://www.mindmeshacademy.com/certifications/aws/aws-certified-machine-learning-engineer-associate/study-guide/3-3-3-debugging-model-convergence-mlflow-tensorboard-and-cloudwatch)) — directly teaches this project's story of **0.97 train accuracy against 0.67 validation**. The confusion matrix defaults to **row-normalized recall view** with a raw-counts toggle, because the Unknown-as-weak-class finding (**test F1 0.46**) only surfaces when the "of actual Unknown, where did predictions go" distribution is visible — matching practitioner guidance that rows are actual classes, columns predicted, cell ink a row-normalized share with an always-present key ([Source](https://microcharts.dev/docs/charts/confusion-grid)), axis labeling with normalization modes and sequential colormaps ([Source](https://anyplot.ai/confusion-matrix)), and one-line W&B logging with hover counts, run toggling, and normalization ([Source](https://docs.wandb.ai/models/ref/python/custom-charts/confusion_matrix)). A per-class precision/recall/F1 plus support table sits beside the matrix, and for imbalanced spotting with dominant Unknown, PR curves belong while ROC stays out of the default view to avoid optimistic reading. In Recharts terms this is multi-series `LineChart` with shared `syncId` tooltips, `Brush` zoom, and `ReferenceLine` target bands ([Source](https://recharts.github.io/en-US/api/LineChart/)).

Isolated-versus-event separation is where evaluator trust is won or lost, because keyword-spotting literature proves **99%+ clip accuracy coexists with hundreds of false alarms per hour** on real negative audio ([Source](https://doi.org/10.3233/faia230695)) and production practice fixes FA/hour first then compares rejection rates across a threshold-swept DET curve ([Source](https://www.isca-archive.org/interspeech_2025/saladukha25_interspeech.pdf)). The dashboard therefore ships two top-level tabs — **"Isolated classification (1-s clips)"** with macro-F1/accuracy vocabulary versus **"Continuous detection (experimental)"** with event precision/recall/F1 plus FA/hour — the continuous tab carrying a persistent banner naming the frozen operating point (**stride 0.2 s, threshold 0.50, min_consecutive 1**), linking the detector JSON and the E02 run, and stating that threshold cannot fix the failure because most false Detections score high. Targets render as fixed reference lines with numeric deltas (**macro-F1 0.740 vs ≥0.85, event-F1 0.007 vs ≥0.70**), axes never rescaled to flatter the gap, every headline metric carrying its denominator (**1017 test clips; 16 keyword events over 561 s Unknown plus 8.8 s Silence in 600 s**). Provenance follows the MLflow/W&B convergence on run-as-primary-key with immutable artifact identifiers and explicit deletion handling ([Source](https://mlflow.org/docs/latest/ml/tracking/)): a run selector keyed by run ID showing truncated checkpoint SHA-256 with copy, dataset/split version, config hash, timestamp, and dirty-flag warning, where switching runs reloads every chart from that run's JSON and never mixes curves across runs, a reproducibility panel with copy-paste commands and manifest hashes, and deletion yielding an explicit "run deleted — views cleared" state rather than silent fallback, consistent with artifact-store gc semantics ([Source](https://mlflow.org/docs/latest/self-hosting/architecture/artifact-store/)). The three empty states stay visually distinct per model-card limitation-reporting norms ([Source](https://huggingface.co/docs/hub/model-cards)): grey **Not evaluated** (no run file for that split), amber/red **target unmet** (number plus delta plus denominator), and a continuous-tab **experimental-only** banner — because the 0.70 target is reported as unmet, never redefined.

## Rewrite ticket 06 in priority order before implementation

The ticket rewrite is itself ordered work: structural decisions first, honesty mechanisms second, interaction detail third. The table below sequences the rewrite so each row unblocks the rows beneath it, with the acceptance criterion an implementer can build against.

| Priority | Rewrite action | Why it blocks everything below |
|---|---|---|
| P0 | Split one ticket into three slice specs with routes `/analyze`, `/live`, `/dashboard` plus shared backend-status pill | Without routing, all three slices contaminate one viewport and one mental model |
| P0 | Write the Analysis async state machine: upload progress vs `queued` vs `running` vs `completed`/`failed` vs `no_detections`, poll cadence, per-state copy and recovery for 409/429/413/503 | "Progress" as one word guarantees one spinner and untriaged queue confusion |
| P0 | Specify the region↔row↔clock linking invariant, wavesurfer.js v7 plugin set (Regions read-only, Timeline, Hover, Zoom), and keyboard-parity controls | Canvas without linking plus keyboard fallback is a mouse-only toy |
| P0 | Specify the mic consent contract: Start-only `getUserMedia`, sticky-denial teaching copy, LISTENING pill, VAD plus level meter, no-retention line, session state machine | Privacy violations and background-mic bugs are ship-blockers, not polish |
| P1 | Specify cooldown plus smoothing numerically (1.2 s lockout, consecutive-frame rule), last-Detection card fields, accepted/rejected visual language, 20-row history | Without visible lockout the demo double-fires and nobody can tell why |
| P1 | Specify the six-Keyword→action allowlist map, stage layout, shared `dispatchAction()` keyboard fallback, utterance-end-to-action latency chip | ADR-0004 compliance must be checkable per Keyword, not asserted in prose |
| P1 | Specify Dashboard tab split (isolated vs continuous), chart set (synced curves, row-normalized matrix default, per-class table), fixed target lines with deltas, denominator placement | Mixed-vocabulary dashboards let 0.74 isolated F1 imply a working detector |
| P1 | Specify provenance selector fields (run ID, checkpoint hash, dataset/split, config hash, dirty flag), switch/delete semantics, reproducibility panel | Numbers without run keys are unverifiable and undeletable |
| P2 | Specify all three empty states (Not evaluated, target unmet, run deleted/missing) plus experimental banner copy with detector link | The current ticket names one of three; evaluators punish the missing two |
| P2 | Specify the full error taxonomy copy: corrupt-file 400s, `no_detections`, mic-denied variants, offline-backend 503s, backpressure notice | Recovery copy cannot be written from four nouns without codes |
| P2 | Specify client pre-checks (extension, size, duration), Keyword chips from active model, delete-confirm copy with cascade warning and 409 disable | Prevents the most common support loop: uploading what the backend rejects |

## Conclusion

The through-line across all three notes is that good interfaces for uncertain audio systems spend their design budget on linkage and honesty rather than density: every Detection must be traceable back to sound, clock, threshold, and run, and every failure must be named with its recovery attached. Rewritten in that spirit, ticket 06 stops being a three-widget page and becomes three small trustworthy tools — a review bench that never shows a number without its waveform, a voice demo that never listens without saying so, and a dashboard that reports its 0.007 as loudly as its 0.97. That inversion, from displaying outputs to proving them, is what turns the detector's no-go verdict from an embarrassment the UI might hide into the project's most demonstrable engineering judgment.
